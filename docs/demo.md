# 리팩토링 계획

검토 대상: `AuthService` 800줄 클래스 분리.

## 1. 현황

- `AuthService` 가 JWT 검증, 세션 관리, 권한 체크를 한 클래스에 담고 있어 변경 영향 범위가 큼
- 단위 테스트가 통합 테스트에 의존해 실행 시간이 길고 실패 원인 추적이 어려움

## 2. 제안

세 개의 책임을 별도 컴포넌트로 분리:

| 항목 | 변경 |
|---|---|
| 분리 1 | `JwtVerifier` — 토큰 검증·갱신 |
| 분리 2 | `SessionStore` — 세션 영속화 |
| 분리 3 | `PermissionChecker` — 권한 정책 평가 |

## 3. 단계

1. 새 컴포넌트의 인터페이스 정의
2. 신규 클래스 구현 + 단위 테스트 추가
3. `AuthService` 에서 신규 컴포넌트로 위임
4. `AuthService` 슬림화 및 deprecated 별칭 유지

## 4. 위험

- 호출처가 50곳 이상 — 마이그레이션 단계에서 호환 레이어 필요
- 분리 후 트랜잭션 경계 재검토 필요
