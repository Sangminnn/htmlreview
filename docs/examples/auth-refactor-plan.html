AuthService 분리 계획

800줄 모놀리식 AuthService 클래스를 세 개의 책임 단위로 분리. 변경 영향 범위 축소 + 단위 테스트 격리 + 정책 변경 용이성이 목표.

현재 vs 분리 후

현재 — AuthService 단일 클래스

JWT 검증 / 세션 관리 / 권한 체크 → 한 클래스 800줄. 변경 영향 큼, 통합 테스트 의존.

분리 후 — 책임별 3 클래스

JwtVerifier / SessionStore / PermissionChecker. 각각 독립 단위 테스트, 정책 교체 시 한 클래스만 수정.

책임현재 메서드분리 후 클래스의존성
토큰 검증·갱신 verifyToken() / refreshToken() JwtVerifier JWKS provider 만
세션 영속화 getSession() / setSession() / invalidate() SessionStore Redis client
권한 정책 평가 checkPermission() / checkRole() PermissionChecker 정책 DSL 파서

분리 후 호출 관계

단계 (각 단계 클릭으로 펼침)

1. 새 인터페이스 정의 · 1주

세 클래스의 public 인터페이스를 TypeScript interface 로 먼저 정의. 구현 없이 contract 만:

interface JwtVerifier {
  verify(token: string): Promise<Claims>;
  refresh(token: string): Promise<string>;
}
interface SessionStore {
  get(id: string): Promise<Session | null>;
  set(id: string, session: Session, ttl?: number): Promise<void>;
  invalidate(id: string): Promise<void>;
}
interface PermissionChecker {
  check(claims: Claims, action: string, resource: string): Promise<boolean>;
}

이 단계가 가장 중요. 인터페이스가 명확해야 다음 단계 위임이 쉬움.

2. 신규 클래스 구현 + 단위 테스트 · 2주

각 클래스 구현 + 단위 테스트. 현재 AuthService 코드를 *복사* 하여 새 클래스에 이식 (이때까지 AuthService 는 그대로).

  • JwtVerifier — JWKS mock 으로 단위 테스트
  • SessionStore — Redis mock 또는 in-memory Map 테스트
  • PermissionChecker — 정책 fixture 로 테이블 테스트
3. AuthService 에서 신규 모듈로 위임 · 2주

AuthService 의 메서드 본체를 *thin wrapper* 로 교체 — 실제 로직은 새 클래스로 위임. 호출자(Controller)는 그대로.

class AuthService {
  constructor(
    private jwt: JwtVerifier,
    private sessions: SessionStore,
    private perms: PermissionChecker,
  ) {}

  // 기존 메서드 → 위임만
  verifyToken(token: string) { return this.jwt.verify(token); }
  getSession(id: string) { return this.sessions.get(id); }
  // ... 50곳 호출처는 영향 없음
}
4. AuthService 슬림화 + deprecated 별칭 유지 · 1주

점진적 deprecation — AuthService 의 메서드를 deprecated 표시하되 *별칭으로 유지*. Controller 들이 한 번에 깨지지 않도록.

4a (위임) → 4b (alias 유지 6주) → 4c (alias 제거 + Controller 직접 호출 변경) 세 단계로 쪼개기.

리스크 매트릭스

리스크심각도완화
호출처 50곳 — 마이그레이션 단계에서 호환 레이어 깨질 위험 높음 4단계 alias 유지 (6주). 깨질 호출처는 grep + CI 에서 미리 잡음
분리 후 트랜잭션 경계 재검토 필요 — 세션 + 권한 동시 update 케이스 중간 두 책임 동시 호출 케이스를 AuthService facade 에서 트랜잭션으로 묶음
JwtVerifier 의 JWKS provider 캐싱 정책 변경 — 기존과 미세 다른 만료 동작 낮음 JWKS provider 인터페이스를 그대로 가져옴 → 동일 동작
